🤖

Analysing a constructor makes Psalm follow every `$this->foo()` and `parent::__construct()` call into the callee to see which properties it initializes (`CallAnalyzer::collectSpecialInformation` -> `ProjectAnalyzer::getMethodMutations`). Each of those builds a `FileAnalyzer` and fetches the statements of the whole declaring file again, and nothing is remembered between calls. With `arrayCache="false"`, the setting Psalm's out-of-memory message recommends, every fetch is a disk read plus an unserialize from the parser cache (`Cache::getItem()` keeps nothing when `arrayCache` is off). So a hot base class is read again for every subclass constructor that calls into it.

#13234 fixed the vendor half of this: vendor files bypass the parser cache, so it keeps their statements serialized in memory from the second request on. Project files still take the parser cache path above, so they are still read again on every call.

## Fix

`getMethodMutations()` keeps the statements of the files it inlines per process, in LRU order, under a fixed 16 MB budget. The size of an entry is the `memory_get_usage()` growth around the fetch. Like #13234, a file is only kept from its second fetch, so files needed once can't push out the hot ones. It is a no-op with `arrayCache` on (the default) and in server and language server mode, where files can change under it. The budget is a private constant; happy to make it a config option if you prefer.

### Same objects, not fresh copies

#13234 hands every request its own copy, unserialized from a string. This returns the same statement objects on each fetch instead, because that is exactly what the default `arrayCache="true"` already does: `Cache::getItem()` returns the array entry it read before. So nothing here sees shared statements that the default config doesn't. A copy per fetch would also keep the unserialize, which is most of what this saves.
